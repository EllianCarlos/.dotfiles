## Question

Can headless runs of `claude -p`, Hermes, opencode, and `agy` add and remove MCP servers while a session is running (not just at launch via a config flag), and if not, what are the workable alternatives (per-stage config generated by the daemon, restarting with `--resume`, a broker MCP that proxies other servers, deferred tool loading)? Capture facts with sources: flags, config files, runtime commands, and any limits on tool-list changes mid-session.

## Resolution

Findings on branch `research/mid-run-mcp-activation-in-headless-agents` (file `docs/wayfinder/pizza-delivery/research/mid-run-mcp-activation-in-headless-agents.md`; throwaway, never merged). Subagent-reported, no live tests run, not independently verified.

- claude 2.1.316: plain `claude -p` fixes its MCP set at launch (`--mcp-config`, `--strict-mcp-config`). The Agent SDK in streaming-input mode documents `setMcpServers()`, `toggleMcpServer()`, `reconnectMcpServer()`, `mcpServerStatus()`. Mid-session tool removal needs 2.1.285+ (met). Under `-p`, `list_changed` refreshes the tool list; tool search lets late-connecting servers appear in the same turn.
- hermes 0.21.5: `/reload-mcp` and a config watcher reload servers between turns; single-query modes have no mid-run refresh. Reload invalidates the prompt cache.
- opencode 2.2.1: docs list `POST /mcp` ("Add MCP server dynamically"), `GET /mcp`, `PATCH /config`, and the CLI has `run --server`; no documented disconnect, and in-flight pickup unverified.
- agy: only `agy mcp add|remove|enable|disable` editing config; treat as launch-time only.
- Alternatives: per-stage generated config with a fresh session or `--resume` is the baseline; a claude streaming session works for claude only; a broker MCP emitting `list_changed` is feasible for claude and Hermes but unverified end to end; claude tool search is the deferred-loading option.
- Open: claude `setMcpServers` details, opencode in-flight pickup, agy per-turn config reads.
